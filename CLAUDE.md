# English — тренажёр английских слов

Приложение для заучивания английских слов интервальными повторениями.
Родственник `greek-vocab`: тот же движок и те же принципы, но подогнан под
английский. План изучения — список Oxford 3000/5000 по уровням CEFR.

**Владелец проекта — не обязательно инженер.** Объясняй результат по-русски и
по делу, не отправляй читать код. Если нужно решение — предлагай вариант,
а не список альтернатив.

## Как устроено

```
data/oxford-5000.tsv        план: 4947 слов с уровнями A1–C1 (из PDF Oxford)
data/*.yaml                 словарь, единственный источник правды
data/irregular-verbs.tsv    неправильные глаголы — закрытый список фактов
   ↓  scripts/build-deck.mjs      валидация + вывод форм по правилам
src/generated/deck.json     собранная колода (в git не хранится)
   ↓  vite
приложение (React, PWA)     прогресс — только в браузере, IndexedDB
```

Одно слово даёт **до шести карточек**, открывающихся по очереди:
`recognize` (EN→RU) → `listen` (на слух) → `spell` (диктант: услышал — записал) →
`produce` (ввод RU→EN) → `cloze` (пропуск в предложении) → `forms` (формы слова).
Следующая ступень появляется, когда предыдущая вышла из фазы обучения.
Расписание считает FSRS (`ts-fsrs`).

Новые слова приходят по уровням: сначала весь A1, потом A2. Внутри уровня —
в порядке словаря, то есть тематическими пачками.

**«Уже знаю»** — отдельное состояние слова, не связанное с карточками
(`progress.known`: id → когда отмечено). Такое слово исчезает из занятий
целиком: и новые ступени, и накопившиеся повторения. Карточки при этом
сохраняются, и «Вернуть в учёбу» в словаре поднимает прогресс с того же места.
Отмечать можно поштучно (кнопка на знакомстве и в словаре) и пачкой
(в словаре кнопка «Уже знаю все» применяется к текущему фильтру).

## Команды

```bash
npm run check        # тесты правил + валидация словаря. Запускать всегда после правки data/
npm run dev          # локально на http://localhost:5173
npm run build        # прод-сборка
npm run coverage     # сколько из плана Oxford разобрано и что дальше
npm run test:morph   # только тесты правил словоизменения
npm run test:answer  # только тесты проверки ответа
npm run test:tts     # только тесты озвучки (на подделке Web Speech API)
npm run test:storage # только тесты переноса прогресса (экспорт → импорт)
npm run test:session # только тесты поведения упражнений
npm run simulate     # прогон 60 учебных дней: видно, во что превратится нагрузка
npm run import:oxford # пересобрать план из PDF (нужны PDF в ../dictionaries)
```

## Коммиты — только по-английски

Сообщения коммитов пишутся **на английском**, даже когда весь остальной разговор
идёт по-русски. Это относится и к заголовку, и к телу.

Комментарии в коде, `CLAUDE.md`, `README.md`, тексты интерфейса и переводы
в словаре остаются по-русски — правило касается только истории git.

Проверяется механически хуком `githooks/commit-msg`: коммит с кириллицей
в сообщении не пройдёт. Хук включается один раз на клон —
`git config core.hooksPath githooks`. Разовый обход: `git commit --no-verify`.

## Правила, которые нельзя нарушать

**0. Написание — половина знания слова.** В английском звук и буквы живут
порознь, поэтому есть отдельная ступень `spell`: слово звучит, ответ набирается.
Опечатка на ней — ошибка, а не мелочь: именно этот навык там и тренируется.
Необязательным считается только служебное «to», артикль, дефис против пробела
и британское написание — они дают вердикт «верно, но пишется иначе».
Закреплено в `scripts/english.test.mjs`.

**1. Не подгонять правило под одно слово.** В `scripts/morphology.mjs` живут
регулярные парадигмы. Если правило разошлось с реальной формой — это почти
всегда исключение в языке, а не ошибка правила. Пометь слово `irregular: true`
и впиши формы руками. Подгонка правила под `leaf → leaves` сломает `roof`,
и заметишь ты это через месяц.

**2. Любое изменение правил — с тестом.** `scripts/morphology.test.mjs`,
173 проверки на заведомо известных парах. Правила существуют затем, чтобы быть
надёжнее человека; непроверенное правило этого свойства не имеет.

**3. Не менять поле `en` у существующего слова.** Идентификатор карточки
строится из написания (`slugify`). Правка `en` создаёт новое слово и **обнуляет
прогресс** по старому. Перевод, пример, формы, тему, часть речи менять
безопасно — прогресс переживёт.

**4. Не редактировать `src/generated/deck.json`.** Он пересобирается при каждом
запуске, правки затрутся. Менять надо `data/*.yaml`.

**5. Пустое значение формы — это заявление, а не пропуск.** `plural: ~` в yaml
значит «такой формы у слова не бывает»: правило её не выведет и в вопросы она
не попадёт. Так помечены месяцы — «Januaries» грамматически возможно, но
спрашивать его незачем. Не путать с отсутствующим ключом: там форма выводится.

**6. Не глушить предупреждения сборки.** Скрипт сообщает о расхождениях с
правилами, дублях, одинаковых переводах и незаполненных формах намеренно.
Пустая клетка честнее выдуманной формы: упражнение просто не спросит её.

**7. Список Oxford — план, а не словарь.** `data/oxford-5000.tsv` собирается
скриптом и правится только им. Слово попадает в занятия, когда у него появился
перевод и тема в `data/*.yaml`.

## Приоритет источников для форм

```
руками (ключ forms: в yaml)  →  data/irregular-verbs.tsv  →  правила
```

Таблица неправильных глаголов закрыта и конечна: это факты языка, а не догадки.
Правила выводят остальное. Любое расхождение между тем, что вписано руками,
и тем, что даёт таблица или правило, печатается списком — разбирать вручную.

## Что уже проверено и переспрашивать не надо

- **Озвучка работает в Safari, в Chrome — нет.** Голоса в Chrome числятся,
  но `speechSynthesis` молчит. Обходы в `src/lib/tts.ts` (сторожевой таймер,
  повтор, удержание ссылки на фразу) уже стоят. Диагностика — в приложении:
  Настройки → Озвучка → «Проверить озвучку».
- **`speechSynthesis.cancel()` нельзя звать на простаивающем движке.**
  В WebKit это сбрасывает разрешение, выданное жестом пользователя, и
  автоматическая озвучка замолкает, хотя по кнопке всё работает. Отменять
  только при `speaking || pending`.
- **`onstart` в WebKit приходит не всегда.** Судить по нему о том, звучит ли
  фраза, нельзя: сторожевой таймер решал, что фразу выбросили, и повторял её —
  слово произносилось дважды. Состояние надо спрашивать у движка.

  Все три бага озвучки закрыты тестами в `scripts/tts.test.mjs` на подделке
  Web Speech API. Прежде чем менять `src/lib/tts.ts`, запусти `npm run test:tts`.
- **Голос предпочитаем американский.** Словарь американский (Oxford American),
  и британское «can't» на карточке диктанта превращает упражнение в другое.
- **Множественное число на `-f`/`-fe` и на согласную + `-o` непредсказуемо:**
  `leaf → leaves`, но `roof → roofs`; `potato → potatoes`, но `photo → photos`.
  Правила нет, есть история каждого слова — такие формы вписываются руками.
- **Удвоение согласной зависит от ударения, а не от букв.** `begin → beginning`,
  но `listen → listening`. Односложные удваивают всегда; для многосложных есть
  закрытый список `FINAL_STRESS` в `scripts/morphology.mjs`.
- **Правила сохраняют регистр слова.** Решения принимаются по строчным буквам,
  а форма строится из исходного написания: иначе `Monday → mondays`,
  а `T-shirt → t-shirts`. Ловится тестом, а в интерфейсе видно сразу.
- **Степени сравнения через more/most — не формы слова, а конструкция.**
  Правило для длинных прилагательных отказывается намеренно, и упражнение
  их не спрашивает: набирать «more beautiful» нечему не учит.

## Проверка интерфейса браузером

Установлен плагин `playwright` — есть навигация, клики, ввод, снимок DOM,
измерение геометрии.

Полезные приёмы:

- **Состояние сеют через IndexedDB** (`keyval-store` → `english-vocab:progress`),
  а не прощёлкивают двадцать карточек. Так можно вывести любой тип упражнения:
  положи карточку нужного `kind` с просроченным `due`. Для карточек с выбором
  из четырёх нужен `state: 1`, для самооценки — `state: 2`.
- **Вёрстку проверяй измерением, а не скриншотом.** Скриншоты Playwright пишет
  в свой изолированный каталог, Read их не видит. `getBoundingClientRect` плюс
  сравнение с `clientWidth` надёжнее и точнее.
- **React не замечает прямой записи в `input.value`** — он отслеживает значение
  сам. Для ввода нужен `browser_type`, иначе фильтр не применится.
- **Синтетический `.click()` не даёт `pointerdown`**, поэтому разблокировка
  озвучки не сработает. Для проверки звука нужен настоящий `browser_click`.
- В headless Chromium **английский голос есть** (Samantha, en-US).

## Грабли

- **YAML: двоеточие внутри незакавыченной строки ломает разбор.**
  `note: Неисчисляемое: two pieces` → нужны кавычки вокруг всего значения.
- **YAML читает `true`, `false`, `yes`, `no`, `on`, `off`, `null` как логические
  значения.** Слово `no` в словаре обязано быть в кавычках: `en: 'no'`.
  Сборка ловит это и говорит прямо, но лучше сразу.
- **`npm run check` обязан работать в чистой копии.** Ничто в нём не должно
  читать `src/generated/deck.json`: этот файл в git не хранится, а режим
  `--check` его намеренно не создаёт. Проверять так:
  `rm src/generated/deck.json && npm run check`.
- **Разбор TSV: не отсекай заголовок по началу строки.** Проверка
  `line.startsWith('word\t')` выкинула из плана слово «word» — и оно потерялось
  из словаря целиком. Заголовки помечены `#`, этого достаточно.
- **HTTP-заголовки только ASCII.** Кириллица в `User-Agent` роняет `fetch`.
- **Прогресс живёт только в браузере.** Смена порядка ступеней или набора типов
  карточек меняет расписание у того, кто уже занимается. Предупреждай об этом.
- **`<StrictMode>` вызывает эффекты дважды.** Отключать нельзя; чинить надо сам
  эффект. Любая функция из `useEffect` должна выдерживать повторный вызов.
- **Одинаковый перевод у двух разных слов — баг, а не мелочь.** На карточке
  RU→EN видно «быстрый», а какое из двух слов вводить — непонятно. Сборка
  предупреждает; переводы надо разводить уточнением в скобках.
- **Скачивание файла: якорь в документ, `revokeObjectURL` — с задержкой.**
  Safari игнорирует `click()` на неприсоединённом якоре, а немедленный отзыв
  blob-ссылки обрывает чтение, и файл сохраняется пустым.

## Готовые навыки

Не изобретай процесс заново — он уже описан:

- `/add-words` — добавить слова: взять следующую порцию из плана Oxford или
  из скриншотов урока, разложить по темам, проверить дубликаты, отчитаться.
- `/publish` — выложить или обновить сайт на GitHub Pages.

## Автопроверка

После правки любого файла в `data/` хук прогоняет `npm run check` и, если
проверка упала, возвращает вывод целиком. Настроен в `.claude/settings.json`,
сама логика — в `scripts/hooks/check-data.sh`.

Это не отменяет ручной проверки: хук ловит поломки, но не подскажет, что
перевод неточен или тема выбрана неудачно.

## Чего не делать без спроса

- Не коммитить и не пушить, пока не попросили.
- Не менять лимиты нагрузки (`newWordsPerDay` и прочее) — это настройки
  пользователя, они живут в приложении.
- Не удалять слова из `data/`. Если слово лишнее — спроси.
- Не трогать `tmp/` — там скриншоты владельца, они вне git.
